# Experimental · 工具箱

包含两个小工具：

- **指数目标价计算器**（`/tools/index-target`）：由杠杆 ETF 目标价反推指数需要的涨跌幅
- **缠论 K 线图**（`/tools/chan-kline`）：基于 lightweight-charts 自动识别并绘制缠论 **笔 / 线段 / 中枢**

---

## 技术栈与运行

- React 19 + TypeScript + Vite
- 图表库：**lightweight-charts ^5.2.1**（v5 API：`addSeries` / `createSeriesMarkers` / `attachPrimitive`）
- **不使用任何第三方缠论库**，所有算法自行实现，且全部为纯函数（不依赖图表实例，便于单元测试）

```bash
npm install
npm run dev    # 开发
npm run build  # tsc -b && vite build
```

当前版本 v0.1.1（主页底部同步显示）。

## 算法定义

流水线：K 线 → 包含合并（4.1）→ 分型（4.2）→ 笔（4.3）→ 线段（4.4）→ 中枢（4.5），全部为纯函数，由 `computeChan` 统一调度。

**交替原则（贯穿全文）**：笔的方向严格交替；线段的方向严格交替；因此构成中枢的三个连续线段必然是「下上下」或「上下上」。`computeChan` 在输出前对线段 / 中枢做结构校验，违规直接抛错，页面不渲染非法结构。

### 4.1 包含处理（merge.ts）

- 判定：`K1.high >= K2.high && K1.low <= K2.low` 或反之 → 存在包含关系
- 向上处理：`newHigh = max(h1,h2)`、`newLow = max(l1,l2)`；向下处理：取小
- 方向判定：每根新 K 线都与最近一根合并 K 线比较——高低点均更高 → 向上，均更低 → 向下；**方向一旦确定即持续有效，直到被新的非包含关系修正**
- 方向未定时（仅可能出现在序列开头）**跳过包含处理**，各根独立保留，待第一对非包含关系的相邻 K 线确定方向后继续正常合并
- 整个处理是**单次前向遍历**：不涉及回溯，同一份数据永远得到同一个合并序列（确定性结果，不影响后续分型与笔的稳定性）
- 输出保留 `originalIndices` 原始索引映射，`highIndex/lowIndex` 记录极值所在原始 K 线，保证分型索引 / 时间戳不错位

### 4.2 分型（fractal.ts）

- 顶分型：中间合并 K 线的高点、低点均严格最高；底分型：均严格最低
- 顶分型取中间 K 线高点、底分型取中间 K 线低点，并记录极值所在原始 K 线索引

### 4.3 笔（stroke.ts，`findBis`）

**方向必须交替**，顶底相连。两种模式（页面可切换，严格笔为默认）：

- **严格笔**（设顶、底分型中间 K 线的合并索引为 i、j）：① 顶底分型不共用合并 K 线（|i − j| ≥ 3）；② 两分型之间至少一根独立合并 K 线（|i − j| ≥ 4）；③ 顶必须高于底。注意索引取**分型中间 K 线**，不要用分型边界索引计算，否则会差 1
- **新笔**：① 顶底分型不共用 K 线（同样要求 |i − j| ≥ 3）；② 顶分型最高 K 线与底分型最低 K 线之间**原始** K 线 ≥ 3 根（不含这两根）；③ 顶必须高于底

**修正规则**：

1. 一笔已成立、反向未成笔就出现新高 / 新低 → 原笔延续至更极端的分型
2. 相邻同性质分型（无反向笔隔开）只保留更极端者
3. 反向分型不满足成笔条件 → 忽略，继续等待

### 4.4 线段（segment.ts，`findSegments`）

**线段的方向必须交替**：向上线段之后必然是向下线段，向下线段之后必然是向上线段，走势表现为「上下上」或「下上下」，不允许出现同向连续线段（不能「上上」或「下下」）。

**构成条件**：

1. 线段至少由**连续三笔**构成，且前三笔必须有**重叠部分**，三笔无重叠不构成线段；
2. 向上线段起始于向上笔，终结于向上笔；向下线段起始于向下笔，终结于向下笔；因此完成线段包含的**笔数必然是奇数**，偶数笔意味着线段尚未完成；
3. 线段方向与首尾笔方向一致，内部笔严格交替：向上线段内部为「上、下、上、下……上」，向下线段为「下、上、下、上……下」。

**确立规则**：新线段生成才能确立前一线段完成；反向线段未生成之前，前一线段延续；笔破坏不必然导致线段结束。

**特征序列法（判定线段结束）**，以向上线段为例：

1. 取该线段中所有**向下笔**构成特征序列；
2. 将特征序列每个元素视为一根 K 线（高点 = 笔起点价，低点 = 笔终点价），做包含处理；
3. 处理后找顶分型；
4. **无缺口**：顶分型第一、二元素间无缺口，则线段在该顶分型高点结束；
5. **有缺口**：需从该高点起的向下笔序列出现底分型，才能确认线段结束。

向下线段对称处理：取所有向上笔构成特征序列，做包含处理后找底分型。

**输出结构**：

```ts
interface Segment {
  startIndex: number;         // 原始 K 线索引
  endIndex: number;
  startTime: number;          // 实现额外附带，供绘制使用
  endTime: number;
  startPrice: number;
  endPrice: number;
  direction: 'up' | 'down';
  biStart: number;            // 起始笔在 Bi[] 中的下标
  biEnd: number;              // 结束笔下标
}
```

**渲染前的方向校验**：绘制前必须校验相邻线段的 `direction` 是否交替，若出现同向连续线段，说明线段划分有误，应抛出错误或回退修正，不允许直接渲染。本项目在 `computeChan` 内置该校验（违规抛错，页面捕获后提示，不渲染非法结构）。

**实现补充**：

- 确认终结前会先校验**反向线段可生成性**：取**候选终结笔之后的连续三笔**（不含候选终结笔本身；笔方向天然交替，故三笔首尾同向），要求其高低区间有共同重叠；不重叠则终结不成立、线段延续（「反向线段未生成之前，前一线段延续」）。若数据不足以构成这三笔，则视为最终线段，不再向后延伸。该检查从算法上保证相邻线段严格交替；
- 数据结尾未确立的发展中线段（≥3 笔且奇数笔）也会输出，便于观察最新走势。

### 4.5 中枢（hub.ts，`findZhongShus`）

**严格定义**：某级别走势中枢，由**至少三个连续次级别走势类型**的重叠部分构成。本项目以**线段作为次级别走势类型**，即：**中枢由至少三个连续线段的重叠部分构成**。

**中枢的方向结构**：因为线段方向严格交替，构成中枢的三个连续线段，其方向必然是：

- 上涨中的中枢：**下、上、下**
- 下跌中的中枢：**上、下、上**

不会出现「上上下」或「下下上」这种结构。

**区间计算**：设三个连续线段 A、B、C 的高低点分别为 (a₁, a₂)、(b₁, b₂)、(c₁, c₂)：

```
中枢下沿 ZD = max(a₂, b₂, c₂)   // 三段低点中的最高者
中枢上沿 ZG = min(a₁, b₁, c₁)   // 三段高点中的最低者
```

若 `ZD >= ZG`，则中枢不成立，继续向后寻找。

**中枢延伸**：前三个线段确定 `[ZD, ZG]` 后，后续线段若仍与 `[ZD, ZG]` 有重叠，则属于中枢延伸，中枢延续、不新开中枢；延伸时区间保持不变（以首三段确定的区间为准）。

**中枢终结**：当某线段**完全离开**中枢区间，且其后的反向线段**不再回到 `[ZD, ZG]` 内**，该中枢终结。「完全离开」指该线段与 `[ZD, ZG]` 无交集——整段最低点 ≥ ZG（完全在上方）或整段最高点 ≤ ZD（完全在下方），边界触碰即视为离开；只要线段与 `[ZD, ZG]` 有交集（哪怕只是部分离开，如高点突破 ZG 但低点仍在区间内），就仍属于中枢延伸。离开后的线段若被其后的反向线段回补，离开段与回补段一并纳入延伸；不回补则中枢终结于最后一个仍有交集的线段。

**输出结构**：

```ts
interface ZhongShu {
  startIndex: number;        // 起始线段对应的原始 K 线索引
  endIndex: number;          // 结束线段对应的原始 K 线索引
  startTime: number;         // 实现额外附带，供绘制使用
  endTime: number;
  zd: number;                // 下沿
  zg: number;                // 上沿
  segmentStart: number;      // 起始线段在 Segment[] 中的下标
  segmentEnd: number;        // 结束线段下标
  direction: 'up' | 'down';  // 中枢形成时所处的走势方向
}
```

**渲染前的结构校验**：绘制中枢前，必须校验构成中枢的线段方向为「下上下」或「上下上」，若出现同向连续线段，说明线段或中枢划分有误，应抛出错误或回退修正。本项目在 `computeChan` 内置该校验（同时校验 `ZD < ZG`）。

## 渲染（ChanKlineChart.tsx）

| 图层 | 样式 |
|------|------|
| K 线 | 红涨 `#f85149` / 绿跌 `#3fb950`（与全站一致） |
| 笔 | 向上 `#ef5350` / 向下 `#26a69a`，线宽 1，按方向拆成两条折线（中间以空白点断开） |
| 线段 | `#2962ff`，线宽 2，只画线段自身起止点 |
| 中枢 | 矩形：填充 `rgba(255,193,7,0.15)`、边框 `#ffc107`（自定义 Primitive）。右边界 = 中枢内**最后一个仍与 [ZD, ZG] 有交集的线段的终点时间**（回补场景取回补段终点，时间上自然覆盖中间的离开段）；终结后的离开段与不回补段不计入矩形 |
| 分型 | `createSeriesMarkers` 顶/底箭头标记 |

- 所有图形锚定 `time` / `price`，缩放平移自动跟随，无像素硬编码
- 图层开关：分型标记 / 笔 / 线段 / 中枢（只切换 `visible` 与数据，不重算）
- 参数：笔模式（严格 / 新笔）、重置按钮；统计条显示各层数量
- 结构校验：线段 / 中枢结构非法时 `computeChan` 抛错，页面捕获后提示，不渲染非法图形

## 验收标准

1. 输入 200 根以上 K 线，能正确画出所有笔，且笔方向交替、顶底相连；
2. 线段至少三笔，笔数为奇数，方向与首尾笔一致，且**相邻线段方向必须交替，不允许同向连续**；
3. 中枢由三个连续线段构成，三段方向必须为「下上下」或「上下上」，区间满足 `ZD = max(三段低点)`、`ZG = min(三段高点)`，且 `ZD < ZG`；
4. 缩放、平移图表时，笔、线段、中枢位置正确跟随；
5. 图层开关（分型 / 笔 / 线段 / 中枢）独立生效；
6. 无控制台报错，无明显性能问题（1000 根 K 线内流畅）；
7. 线段 / 中枢结构校验失败时抛出错误并在页面提示，不渲染非法结构。

## 代码结构

```
src/
  pages/ChanKline.tsx            # 页面：数据加载、参数控制、统计
  components/
    ChanKlineChart.tsx           # lightweight-charts 渲染封装
    HubRectPrimitive.ts          # 中枢矩形自定义图元
  lib/chan/
    index.ts                     # 统一入口 computeChan(klines, biMode?) + 结构校验
    types.ts                     # Kline / MergedKline / Fractal / Bi / Segment / ZhongShu
    merge.ts                     # 4.1 包含处理
    fractal.ts                   # 4.2 分型识别
    stroke.ts                    # 4.3 笔识别（严格 / 新笔）
    segment.ts                   # 4.4 线段识别（特征序列法）
    hub.ts                       # 4.5 中枢识别
    csv.ts                       # SOXL.csv 解析
```

统一计算入口：

```ts
computeChan(klines: Kline[], biMode: BiMode = "strict"): {
  merged: MergedKline[];
  fractals: Fractal[];
  bis: Bi[];
  segments: Segment[];
  zhongshus: ZhongShu[];
}
```

## 明确不做的事
